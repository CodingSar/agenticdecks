# Clean Code & Design Patterns — changelog (composer)

**Scope.** Clean Code and SOLID, all 23 Gang of Four (GoF) patterns, and the patterns and ideas that came after (Fowler's *Refactoring* 2nd ed., Kerievsky's *Refactoring to Patterns*, Bloch's *Effective Java*, Nystrom's *Game Programming Patterns*, Wlaschin's *Domain Modeling Made Functional*, King's "Parse, don't validate", Metz, Page-Jones on connascence). Every card is anchored in a concrete code situation: *which pattern for this scenario, which smell calls for it, what it costs, when not to use it, and where it lives in real libraries* (JDK, Spring, Express/ASP.NET middleware, React, Redux, Go `io.Reader`, Kubernetes). Composed from four writer parts (A 112, B 91, C 130, D 137 = 470 in), merged to **458 notes / 511 cards**, 115 notes with an analogy (25 %), 19 hand-drawn SVGs.

**Subdeck outline (notes).** 01 Clean Code: Names, Functions & Comments 31 · 02 Clean Code: Objects, Errors, Boundaries & Tests 33 · 03 SOLID & Design Principles 47 · 04 GoF Creational 41 · 05 GoF Structural 50 · 06 GoF Behavioural I (Chain of Responsibility, Command, Interpreter, Iterator, Mediator, Memento) 41 · 07 GoF Behavioural II (Observer, State, Strategy, Template Method, Visitor) 39 · 08 Choosing a Pattern: Scenario to Pattern 46 · 09 Refactoring: From Smell to Pattern 37 · 10 Beyond GoF: Modern Object Patterns 36 · 11 Functional & Type-Driven Design 28 · 12 Anti-patterns & Patterns in the Wild 29.

**Per-pattern shape (04–07).** Intent ("what varies?") · 1–3 concrete when-to-use scenarios across e-commerce, games, UI, compilers, cloud/Kubernetes and testing · the code smell that signals it · cost / when not to use it · a real-world anchor · modern-language notes where they change *when* you'd use it (Builder ↔ named arguments, Strategy ↔ function values, Visitor ↔ sealed types + `switch`, Singleton ↔ one instance wired by dependency injection) · short `<pre><code>` sketches. Subdeck 08 has one scenario per GoF pattern in domains different from 04–07, "what varies here?" diagnosis cards, ten cross-category contrasts (Strategy vs State, Strategy vs Template Method, Strategy vs Command, Command vs Memento, Observer vs Mediator, Mediator vs Facade, Chain of Responsibility vs Decorator, Visitor vs pattern matching, Iterator vs generator, Interpreter vs parser library) and "patterns that appear together".
