# The Chomsky Hierarchy

## Essence

The Chomsky hierarchy ranks grammars by how much freedom their rules have and pairs each rank with a class of machines by how much memory those machines have. Four levels result: regular (finite memory), context-free (one stack), context-sensitive (memory proportional to the input) and recursively enumerable (unbounded tape). Each level strictly contains the one below, and moving up buys expressive power at the cost of decidability and efficiency. The hierarchy's main lesson for engineers is a design rule: describe a problem with the weakest formalism that fits it, because every question you might ask gets harder, and eventually unanswerable, as you climb.

## Core tenets

1. **Four grammar types, defined by rule shape.** With A, B variables, a a terminal and α, β, γ strings:

   | Type | Rule form | Languages | Machine | Memory |
   |---|---|---|---|---|
   | 3 | A → aB or A → a (right-linear) | Regular | Finite automaton | Constant |
   | 2 | A → γ | Context-free | Pushdown automaton | One stack |
   | 1 | αAβ → αγβ, γ non-empty | Context-sensitive | Linear-bounded automaton | Linear in input |
   | 0 | α → β (any) | Recursively enumerable | Turing machine | Unbounded |

   Restricting the left side to one variable (type 2) removes context; restricting the right side to "terminal then at most one variable" (type 3) removes nesting.

2. **The inclusions are strict, and each has a witness.** {aⁿbⁿ} is context-free but not regular (pumping lemma). {aⁿbⁿcⁿ} is context-sensitive but not context-free (pumping lemma for context-free languages (CFLs)). The halting language is recursively enumerable but not context-sensitive (it is not even decidable). Some decidable languages lie strictly between context-sensitive and recursively enumerable, so the levels are not the only interesting boundaries.

3. **Memory is what separates the levels.** A finite automaton remembers a bounded amount, so it cannot count. A stack remembers unboundedly but can only consult its top, so it matches one nested pair of counts. A Linear-Bounded Automaton (LBA) can revisit its whole input in place. A Turing machine can use as much tape as it likes. The machine column is the real explanation of the grammar column.

4. **Decidability erodes as you climb.** For regular languages, membership, emptiness and equivalence are all decidable and fast. For context-free languages, membership and emptiness are decidable but equivalence and universality are not. For context-sensitive languages, membership is decidable (an LBA has finitely many configurations on a given input, so you can detect loops) but emptiness is not. For type 0, even membership is undecidable: this is the [halting problem](../03-computability/halting-problem-and-undecidability.md).

5. **Efficiency erodes too.** Regular membership is O(n) with constant memory; context-free membership is O(n³) in general and O(n) for deterministic grammars; context-sensitive membership is PSPACE-complete in general (PSPACE: solvable in polynomial memory); type-0 membership has no algorithm at all. So the hierarchy is also a ladder of [complexity classes](../04-complexity/complexity-classes.md): context-sensitive languages are exactly NSPACE(n) (nondeterministic space), the languages decidable in linear nondeterministic space.

6. **Unrestricted grammars are as powerful as any computer.** Type-0 rewriting can simulate a Turing machine step by step (the sentential form encodes the tape), and a Turing machine can enumerate all derivations. So "language generated by some grammar" and "language recognised by some program" coincide, an early instance of the convergence behind the [Church–Turing thesis](../03-computability/church-turing-thesis.md).

7. **Use the weakest level that fits.** Tokens are regular, so lexers use DFAs; syntax is (deterministic) context-free, so parsers use LR or LL algorithms (deterministic left-to-right parsing with bounded lookahead); scoping and typing need more, so they are handled by separate passes. The same principle drives configuration languages, query languages and data formats: less power means more can be checked, optimised and guaranteed to terminate. This is sometimes called the "principle of least power".

## Key concepts

| Term | Meaning |
|---|---|
| Rewriting system | Rules that replace substrings; grammars are a special case |
| Type 0–3 | Chomsky's four levels, from unrestricted to regular |
| Linear-bounded automaton | Nondeterministic Turing machine confined to the input's cells |
| Recursively enumerable | Some machine accepts exactly the members (may loop on non-members) |
| Decidable (recursive) | Some machine halts on every input with the right answer |
| Mildly context-sensitive | Classes (e.g. tree-adjoining grammars) just above CFL, used for natural language |

## How it fits

- **Below:** It ranks the machines of [finite automata](finite-automata-and-regular-languages.md) and [pushdown automata](context-free-grammars-and-pushdown-automata.md) by set inclusion, a [partial order](../../01-mathematical-foundations/02-sets-relations-functions/relations-and-orders.md).
- **Above:** It shapes the front end of every compiler ([lexing and parsing](../../06-programming-languages/03-compilers/lexing-and-parsing.md)) and the choice between expressive and analysable notations for [syntax](../../06-programming-languages/02-semantics-and-types/syntax-and-semantics.md). Input-handling security ("LangSec") argues that parsers for untrusted input should accept the weakest language class possible ([web security](../../11-security-and-cryptography/04-network-and-application-security/web-security.md)). Natural language sits slightly above context-free, a point that mattered for classical [knowledge representation](../../13-artificial-intelligence/01-classical-ai/knowledge-representation-and-reasoning.md) and parsing.
- **Siblings:** This leaf summarises and connects the two leaves before it, and its top level hands off to [Turing machines](../03-computability/turing-machines.md) in the computability area.

## Common misconceptions

- **"The hierarchy classifies all languages."** It has four named levels, but there are uncountably many languages and only countably many grammars, so almost all languages are not even type 0.
- **"Higher is better."** Higher levels describe more, but you can prove and optimise less about them. Engineering usually wants the lowest level that suffices.
- **"Context-sensitive means what it sounds like in programming."** Real "context" rules (declare before use) are usually enforced by symbol tables, not context-sensitive grammars, which are rarely used directly because their parsing is PSPACE-complete.
